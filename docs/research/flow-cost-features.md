# Flow Cost: расширенный каталог функций

Дата: 2026-11-13. Дополняет [flow-cost-idea.md](flow-cost-idea.md). Это каталог идей с приоритетами, а не спецификация: правила расчёта и макеты будут в отдельном документе.

Принципы продукта:

- Всё локально: без сети, аккаунтов, ИИ и аналитики. Это одновременно требование и аргумент в листинге (так делают Prototype Flow Auditor и Preflight).
- Любая цифра объяснима: рядом всегда виден разбор «из чего сложилось». Пользователь может поправить допущения, и результат пересчитается.
- Плагин ничего не меняет в дизайне без явной команды. Метки и настройки пишутся только в `pluginData`, наложения на холст строятся в отдельной группе, которую можно удалить одной кнопкой.
- Один плагин вместо трёх: структурная проверка графа входит в состав, чтобы не ставить Flow Auditor отдельно.

Теги источника: **[заимств.]** идея взята у существующего плагина или метода, **[своё]** придумано здесь.

## Модуль B. Модели стоимости

| #   | Функция                                                                                                                                                                                                                                 | Источник                                                                       |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| B1  | Счётчики: шаги, тапы, экраны, оверлеи, уникальные экраны, возвраты                                                                                                                                                                      | [заимств.] словарь метрик из Lyssna/UserTesting («clicks», «steps»)            |
| B2  | Время по KLM: K (набор), P (указание), H (возврат рук), M (мысленный шаг), R (ответ системы). Базовые значения из оригинала: P 1,1 с, H 0,4 с, M 1,35 с, K от 0,08 до 1,2 с по навыку набора                                            | Keystroke-Level Model (Card, Moran, Newell)                                    |
| B3  | Профили: эксперт / обычный / новичок, устройство мышь / касание / клавиатура. Операторы касаний (тап, свайп, жест) по Touch Level Model (Rice, Lartigue)                                                                                | KLM + TLM, [своё] выбор профилей                                               |
| B4  | Закон Фиттса вместо фиксированного P: `MT = a + b·log2(D/W + 1)`, D берётся из расстояния между центрами зон нажатия соседних шагов, W по правилу «меньшая из сторон» или «W-model» (выбор в настройках). Константы a и b редактируются | Fitts, [своё] применение к геометрии прототипа                                 |
| B5  | Стоимость набора текста: число символов берётся из текста-образца поля или вводится вручную                                                                                                                                             | [своё]                                                                         |
| B6  | Стоимость прокрутки: если зона нажатия ниже границы экрана, добавляется оператор прокрутки (по `overflowDirection` и высоте содержимого)                                                                                                | [своё]                                                                         |
| B7  | Стоимость выбора по Хику: чем больше конкурирующих целей на экране, тем больше `log2(n+1)` к мысленному шагу                                                                                                                            | Hick's law, [своё]                                                             |
| B8  | Стоимость чтения: слова на экране ÷ скорость чтения заменяют часть M для экранов с большим текстом (переключатель)                                                                                                                      | [своё]                                                                         |
| B9  | Ответ системы R: из `AFTER_TIMEOUT` и длительности перехода (единицы `duration` нужно проверить зондом, документация их не называет)                                                                                                    | [своё]                                                                         |
| B10 | Режим «дотянуться до зоны большого пальца» для мобильных: множитель к P по положению цели на экране и выбранной руке                                                                                                                    | [заимств.] ThumbSpan проверяет достижимость; здесь это входит в стоимость пути |

Осторожность с формулировками: KLM описывает опытного пользователя без ошибок, Dunlop и Crossan считают его неточным для мобильных. В интерфейсе плагина оценка называется «модельная оценка», не «время пользователя».

## Модуль J. Ручные уточнения (чтобы эвристики не мешали)

- Отметить элемент как «ввод текста» с числом символов, «чтение», «решение», «ожидание».
- Отметить экран как «финальный», «служебный» (не считается шагом), «точка решения».
- Все пометки хранятся в `pluginData` у узлов и переживают закрытие файла.
- Автоопределение полей ввода по типу компонента и именам слоёв, с очевидным способом исправить.

## Что сознательно не делаем

- Метрики реальных пользователей (клики, тепловые карты): для этого нужен сервер и сессии, и эту нишу занимают TapTail, Pathway, Wynde.
- ИИ-оценки и «советы по дизайну»: результат недетерминирован, и ниша переполнена.
- Любая сеть и аккаунты.
- Изменения дизайна без команды пользователя.

## Технические вопросы для зонда (до спецификации)

1. Единицы `Transition.duration` в Plugin API (документация не уточняет).
2. Как читать `CONDITIONAL`: форма условий и ветвей.
3. Производительность обхода страницы с тысячами слоёв: нужен поиск узлов с `reactions` без полного обхода дерева.
4. Как определить высоту содержимого и фиксированные дочерние элементы для прокрутки (`overflowDirection`, `numberOfFixedChildren`).
5. Доступ к `reactions` при `documentAccess: "dynamic-page"`: нужны асинхронные методы загрузки страниц.
6. Что считать зоной нажатия, если у реакции нет явной области: сам узел с реакцией или его ближайший интерактивный предок.
7. Значения порогов размера цели по платформам и константы Фиттса: зафиксировать с источниками в спецификации.
