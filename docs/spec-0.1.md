# Flow Cost 0.1: спецификация

Версия 0.1 берёт из [каталога функций](research/flow-cost-features.md) минимум, который уже полезен. Язык реализации: TypeScript 7 strict. Состав: A1–A6, B1–B5 и B9, C1–C3, D1, F1–F3, G1–G2, J. Всё, чего здесь нет, откладывается.

## Решения, принятые по умолчанию

Открытые вопросы из исследования закрыты так, чтобы работа могла начаться. Любое решение можно пересмотреть без переделки движка: допущения лежат в одном объекте и правятся в окне плагина.

| Вопрос                        | Решение                                                                                                                                                |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Что считается экраном         | Фрейм верхнего уровня страницы или фрейм внутри секции верхнего уровня                                                                                 |
| Куда ведёт цель внутри экрана | Цель `destinationId` поднимается до своего экрана; цель на другой странице или удалённая считается битой                                               |
| Зона нажатия                  | Ограничивающая рамка узла с реакцией, в координатах своего экрана. У реакции на самом фрейме экрана это весь экран                                     |
| `NAVIGATE`                    | Стек состояний заменяется целью                                                                                                                        |
| `OVERLAY`                     | Цель кладётся на стек, действия доступны только на верхнем слое                                                                                        |
| `SWAP`                        | Верхний слой заменяется целью                                                                                                                          |
| `CHANGE_TO`, `SCROLL_TO`      | Состояние экрана не меняется: в поиске пути не участвуют                                                                                               |
| `BACK`, `CLOSE`, `URL`        | В поиске пути не участвуют: возвращают в уже посещённое состояние или выходят из прототипа                                                             |
| `CONDITIONAL`, `SET_VARIABLE` | Условные ветки считаются возможными путями, значения переменных не симулируются; такие связи помечены «допущение»                                      |
| Триггер `AFTER_TIMEOUT`       | Шаг без действия пользователя: только ожидание                                                                                                         |
| Триггер `ON_HOVER`            | Указание без нажатия: в поиске пути не участвует                                                                                                       |
| Поля ввода                    | Определяются по эвристике (имя слоя) и ручным отметкам; стоимость добавляется, когда путь проходит через экран                                         |
| Константы модели              | Рабочие допущения, источники не зафиксированы кроме оригинальных значений KLM (M 1,35, H 0,4, P 1,1, B 0,1, K 0,12 / 0,28 / 0,50). Все правятся в окне |
| Языки                         | Интерфейс на английском, документы на русском                                                                                                          |

## Модель данных

`FlowGraph` не зависит от Figma, он строится в Plugin Main и целиком уходит в окно.

- `Screen`: `id`, `name`, размеры, высота содержимого (для прокрутки), признак прокрутки, отметка «финальный», поля ввода.
- `Link`: экран-источник, узел-источник, рамка, триггер, ожидание, тип навигации, цель или `null`, причина поломки, признак условной ветки, длительность перехода.
- `starts`: точки входа потоков страницы.

## Расчёт

Состояние поиска: стек экранов плюс последняя использованная связь (она задаёт точку, откуда указатель идёт к следующей цели).

Стоимость шага складывается из операторов KLM:

1. M: мысленный шаг перед действием пользователя.
2. Для каждого поля ввода экрана: указание, нажатие, H, K × число символов, H.
3. Прокрутка S, если цель ниже границы экрана.
4. P: время указания. Закон Фиттса `a + b·log2(D/W + 1)`, где D расстояние между центрами зон, W меньшая из сторон цели; либо фиксированное значение.
5. B: нажатие или касание.
6. R: ожидание перехода и таймеров.

Находятся: кратчайший по числу шагов путь, кратчайший по времени путь и до 50 альтернативных путей глубиной до 12 шагов.

Результат называется «модельной оценкой». Это не время реального пользователя.

## Точки трения

Мелкая цель (меньше 44 для касания, меньше 24 для мыши), далёкая цель (индекс сложности выше порога), оверлей на пути, прокрутка до цели, форма из четырёх и более полей, ожидание дольше секунды.

## Проверка графа

Нет точки входа, битая цель, недостижимый экран, экран без выхода (не отмеченный финальным), оверлей без выхода.

## Сравнение

Снимок сохраняет итоги расчёта в общих данных плагина корня документа (`getSharedPluginData`, пространство `flowcost`, ключ `snapshots`; приватные данные не подходят, пока в манифесте нет `id`). Сравнение «снимок против текущего»: разница шагов, времени, тапов, символов и точек трения.

## Экспорт

Markdown (итоги, таблица шагов, допущения) и CSV (трасса операторов), копируются в буфер.

## Окно плагина

Вкладки: Analyze, Health. Analyze: выбор начального и целевого экрана (список и «взять из выделения»), профиль, допущения, результат с трассой, альтернативы, точки трения, сравнение со снимком, экспорт. Health: список проверок; клик по записи выделяет слой.

## Протокол окно ↔ Plugin Main

Окно просит прочитать страницу (`SCAN`), показать слой (`REVEAL`), поставить или снять отметку (`MARK`), сохранить, прочитать, удалить снимок. Plugin Main присылает граф, выделение, список снимков, ошибки. Настройки хранятся в `clientStorage`.

## Что не входит в 0.1

Закон Хика, чтение, зона большого пальца, наложения на холст, симуляция переменных, клавиатурная стоимость, калибровка, тест-кейсы.

## Проверка

Движок покрывается модульными тестами на примерах графов (линейный путь, ветвление, оверлей, `SWAP`, цикл, недостижимая цель, формы, прокрутка). Чтение Figma проверяется вручную в Figma Desktop по протоколу из `docs/manual-checks.md`; пока не проверено.

## Дополнение: закон Хика и метрики сценария

Добавлено после первой реализации.

- **Закон Хика.** К шагу добавляется оператор C: `hickB × log2(n)`, где n число элементов экрана, на которые реагирует прототип (слои, а не связи; таймеры не считаются). При одном элементе выбора нет, и C равен нулю. Настройки: переключатель, `hickB` (рабочее допущение 0,15 с на бит), порог «много вариантов» (7). Экран с таким числом вариантов и больше даёт точку трения «Many options».
- **Точки выбора.** Число действий на пути, сделанных на экране с несколькими вариантами.
- **Стоимость возврата.** Для каждого шага: сколько действий нужно, чтобы вернуться на экран, который он покинул. Один, если на новом экране есть `BACK` или `CLOSE`; иначе кратчайший путь по связям. Если пути нет, шаг считается «без возврата». Показываются число таких шагов и самый длинный возврат.
- **Структура сценария.** Среди экранов, лежащих на каком-либо пути от старта к цели: их число, число связей, число экранов с развилкой и число независимых маршрутов (связи − экраны + 2, для прямой линии 1).
- Снимки и экспорт включают точки выбора и шаги без возврата; Markdown показывает число экранов в игре и независимых маршрутов.

## Статус реализации

Реализовано: всё из состава версии 0.1. Отличия от черновика: триггеры `ON_HOVER` в поиске пути не участвуют (как и в таблице решений); единицы `Transition.duration` и `AFTER_TIMEOUT.timeout` читаются как секунды, значения больше 30 как миллисекунды (в типах Plugin API duration даётся в секундах, для `timeout` единицы типами не заданы: проверить в Figma, строка 12 протокола ручной проверки).
