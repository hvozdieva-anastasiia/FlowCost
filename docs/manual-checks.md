# Ручная проверка в Figma Desktop

Автоматические тесты покрывают движок расчёта, разбор реакций, протокол и окно с подставным каналом связи. Чтение настоящего прототипа Figma ими не проверено: это делается вручную по списку ниже. Отмечать результат в таблице внизу.

## Подготовка

1. `pnpm build`.
2. Figma Desktop: Plugins → Development → Import plugin from manifest → `manifest.json`.
3. После первого импорта записать выданный ID: `pnpm plugin:id <ID>`.
4. Открыть тестовый файл с прототипом: страница из 5–6 экранов, связи `NAVIGATE`, один `OVERLAY` с кнопкой закрытия, один `SWAP`, один таймер `AFTER_TIMEOUT`, один `CONDITIONAL`, экран с полем ввода (слой с именем «Email input»), прокручиваемый экран с целью ниже границы, точка входа потока.

## Результаты

Окно плагина в Figma Desktop не запускалось: доступ к приложению не был выдан. Часть проверок выполнена иначе, на тестовом файле «Flow Cost test prototype» (аккаунт, подключённый к Figma MCP): код чтения страницы (`src/plugin/extract.ts`, собран esbuild) выполнен через `use_figma`, результат сохранён как `tests/fixtures/figma-signup.json` и используется в `tests/engine/figma-fixture.test.ts`. Окно (`dist/index.html`) открыто в браузере панели, граф подан сообщением `SCAN_RESULT`.

Через `use_figma` нельзя вызывать `getPluginData` и `setPluginData` (хост их не поддерживает), поэтому при проверке чтения они были заменены заглушками. Метки, снимки и настройки не проверены.
