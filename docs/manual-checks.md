# Ручная проверка в Figma Desktop

Автоматические тесты покрывают движок расчёта, разбор реакций, протокол и окно с подставным каналом связи. Чтение настоящего прототипа Figma ими не проверено: это делается вручную по списку ниже. Отмечать результат в таблице внизу.

## Подготовка

1. `pnpm build`.
2. Figma Desktop: Plugins → Development → Import plugin from manifest → `manifest.json`.
3. После первого импорта записать выданный ID: `pnpm plugin:id <ID>`.
4. Открыть тестовый файл с прототипом: страница из 5–6 экранов, связи `NAVIGATE`, один `OVERLAY` с кнопкой закрытия, один `SWAP`, один таймер `AFTER_TIMEOUT`, один `CONDITIONAL`, экран с полем ввода (слой с именем «Email input»), прокручиваемый экран с целью ниже границы, точка входа потока.

## Результаты

Плагин импортирован из манифеста и запущен в Figma Desktop (версия 126.11.8) на тестовом файле «Flow Cost test prototype», тёмная тема Figma. Проверки выполнялись через управление рабочим столом; запись в файл проверялась независимо через `use_figma`. Граф, прочитанный реальным кодом плагина, сохранён как `tests/fixtures/figma-signup.json` и используется в `tests/engine/figma-fixture.test.ts`.

Найдено и исправлено при проверке: приватные данные плагина (`getPluginData`, `setPluginData`) не работают у плагина без `id` в манифесте («Cannot get private plugin data in a plugin without an ID»): чтение страницы падало. Метки и снимки переведены на общие данные плагина (`getSharedPluginData` с пространством имён `flowcost`), они работают без `id`. Через `use_figma` общие данные читать можно, приватные нельзя.
